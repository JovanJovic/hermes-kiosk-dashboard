## Writing standard: ASD-STE100

Use ASD-STE100 (Simplified Technical English) as the default standard for new and revised English project prose. This includes Jira tickets, requirements, acceptance criteria, SOPs, technical documentation, investigation reports and project explanations.

- Follow the applicable writing rules and dictionary. Use permitted technical nouns and verbs consistently.
- Use short, clear sentences and active voice where applicable. Give one instruction per step. State a necessary condition before its action.
- Use one consistent term for each concept. Preserve exact UI labels, code and SQL identifiers, API names, status codes, quotations and source evidence.
- Preserve technical meaning, evidence, uncertainty and existing confidence labels. Simplification must not turn an inference into a confirmed fact.
- Keep required document structures, audience needs and explicit project spelling requirements.
- Apply this standard to prose. It does not authorize code or identifier changes, historical-document rewrites, or changes to access and safety rules.
- Do not claim verified ASD-STE100 compliance unless the text has been checked against the full applicable rules and dictionary. Clearly distinguish an STE-based draft from verified compliance.

Reference baseline: ASD-STE100 Issue 9 (15 January 2025), https://www.asd-ste100.org/.
